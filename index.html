      control(sensors) at 20 Hz returns (steering, throttle). Steering is radians, positive left. Throttle is −1…1. Python sees sensors only.

      Sensor API
      • sensors.time, sensors.dt — seconds.
      • sensors.lidar.ranges, .angles, .max_range — a beam at max range missed.
      • sensors.odometry.speed, .steering_angle, .pose.x, .pose.y, .pose.yaw.
      • sensors.imu.yaw_rate, .accel.x, .accel.y, .accel.z.
      • sensors.task.path, sensors.task.map — a route and a floor plan, not a measurement of the car.
      • Your car remembers things between ticks in one object called run. class Run lists what it remembers: a tick counter, the last error, whatever you need. At the start of every run, init(sensors) makes a fresh Run, so each drive begins with a clean memory. Inside control, read and change it directly: run.ticks += 1. Settings that never change, like a target speed, can stay plain names at the top of the file. That's it: one object, reset every run.
      • SEED — draws the sensor bias once. The same number replays the same noise. Use it for np.random.default_rng(SEED) too.
      • START_POSE — where the car is placed on Run and Reset. x and y are meters (y runs north), then heading in degrees. 0 faces north, and 90 faces east. This is not a sensor reading.
      • There is no true pose on sensors.
